# NCR Suite V2.21.1

## Objet

La V2.21.1 complète le centre de démarrage avec une reprise de données Formation contrôlée avant import.

Les imports déjà disponibles restent inchangés :

- stagiaires ;
- formateurs ;
- programmes.

Les nouveaux imports concernent :

- entreprises clientes ;
- financeurs ;
- prospects et opportunités CRM ;
- sessions ;
- inscriptions et informations utiles au BPF.

## Ordre conseillé

1. Entreprises clientes.
2. Financeurs.
3. Stagiaires.
4. Formateurs.
5. Programmes.
6. Prospects CRM.
7. Sessions.
8. Inscriptions.

Chaque rubrique fournit son propre modèle CSV. Le fichier est vérifié par Supabase avant toute écriture. Lorsqu’une erreur est détectée, aucune ligne n’est ajoutée et un rapport CSV peut être téléchargé.

## Protection des automatisations

- Une session à venir portant le statut `scheduled` ou `in_progress` est importée en brouillon.
- L’utilisateur la vérifie ensuite dans **Sessions** avant de la valider.
- Cette validation normale déclenche seulement les automatisations utiles à la future session.
- Une session historique portant le statut `completed` est importée comme réalisée, sans renvoyer d’anciens e-mails, questionnaires ou attestations.
- Les inscriptions historiques peuvent inclure la catégorie BPF et les heures réellement suivies.

## Déploiement

### 1. Supabase

Exécuter intégralement :

`supabase/migrations/083_training_data_recovery.sql`

Contrôler ensuite :

```sql
select
  database_version,
  expected_frontend_version,
  expected_pwa_cache
from public.platform_release_state
where singleton = true;
```

Résultat attendu :

```text
2.21.1 | 2.21.1 | ncr-suite-shell-v2.21.1-training-data-recovery
```

Aucune fonction Edge supplémentaire n’est nécessaire pour cette version.

### 2. GitHub

Envoyer tous les fichiers du patch en conservant leur arborescence. Vérifier que le dépôt affiche `2.21.1` dans `package.json`.

### 3. Cloudflare

Le build doit exécuter :

```text
npm run build
```

Le dossier de sortie reste :

```text
dist
```

Le journal doit annoncer `ncr-suite@2.21.1` et valider les trois contrôles automatiques avant la compilation Vite.

### 4. Cache PWA

Fermer puis rouvrir NCR Suite après le déploiement. Le cache attendu est :

```text
ncr-suite-shell-v2.21.1-training-data-recovery
```

### 5. Tests fonctionnels

1. Ouvrir **Centre de démarrage** dans un espace Formation.
2. Télécharger le modèle **Entreprises clientes**.
3. Importer un fichier contenant une ligne valide et vérifier le contrôle préalable.
4. Réimporter le même fichier et vérifier que la ligne apparaît comme doublon.
5. Tester un fichier avec une donnée obligatoire manquante et télécharger son rapport d’erreurs.
6. Importer une session `scheduled` et vérifier qu’elle apparaît en brouillon.
7. Importer une session historique `completed` et vérifier qu’aucun e-mail ancien n’est ajouté à la file.
8. Importer les inscriptions correspondantes et contrôler les catégories BPF et les heures suivies.

## Retour arrière

En cas d’erreur avant l’envoi GitHub, ne pas poursuivre le déploiement. La migration est idempotente et peut être corrigée puis réexécutée. Les imports utilisateurs ne sont lancés qu’après la mise en ligne complète de la V2.21.1.
