# NCR Suite V2.22.0 - Installation

Cette version part de la V2.21.2 stable avec les migrations `001` à `087`
déjà exécutées. Respecter l’ordre ci-dessous.

## 1. Sauvegarde

Dans Supabase, vérifier qu’une sauvegarde récente est disponible. Ne supprimer
aucune migration et ne rejouer aucune ancienne migration.

## 2. SQL Supabase

Ouvrir `SQL Editor > New query`, coller tout le fichier :

```text
supabase/migrations/088_commercial_launch_controlled_access.sql
```

Exécuter une seule fois. Le résultat final doit être `Success. No rows
returned`. Cette migration crée les demandes d’accès, le journal anti-abus,
verrouille la création d’entreprise et synchronise la validation V2.22.0.

## 3. Secrets des Edge Functions

Dans `Supabase > Edge Functions > Secrets`, ajouter :

```text
BREVO_API_KEY=VOTRE_CLE_API_TRANSACTIONNELLE_BREVO
BREVO_SENDER_EMAIL=contact@ncr-suite.fr
BREVO_SENDER_NAME=NCR Suite
NCR_SUITE_PUBLIC_URL=https://ncr-suite.fr
NCR_SUITE_ALLOWED_ORIGINS=https://ncr-suite.fr,https://www.ncr-suite.fr,https://ncrsuite.pages.dev
TURNSTILE_SECRET_KEY=VOTRE_CLE_SECRETE_TURNSTILE
ACCESS_REQUEST_HASH_SALT=UNE_VALEUR_ALEATOIRE_LONGUE_ET_UNIQUE
```

Conserver aussi les secrets déjà utilisés par `process-email-queue`, notamment
`EMAIL_PROCESSOR_SECRET`. `SUPABASE_URL` et `SUPABASE_SERVICE_ROLE_KEY` sont
fournis automatiquement par Supabase.

## 4. Edge Functions Supabase

Créer ou mettre à jour les fonctions avec les fichiers du même nom :

| Fonction | Fichier | Verify JWT |
| --- | --- | --- |
| `request-platform-access` | `supabase/functions/request-platform-access/index.ts` | désactivé |
| `admin-review-access-request` | `supabase/functions/admin-review-access-request/index.ts` | activé |
| `request-account-recovery` | `supabase/functions/request-account-recovery/index.ts` | désactivé |
| `process-email-queue` | `supabase/functions/process-email-queue/index.ts` | désactivé |

Déployer les quatre fonctions et vérifier que leur statut est `Active`.

## 5. Auth Supabase

Dans `Authentication > URL Configuration` :

```text
Site URL
https://ncr-suite.fr

Redirect URLs
https://ncr-suite.fr/activation
https://ncr-suite.fr/configuration
https://ncr-suite.fr/administration-ncr
```

Ne pas remettre une URL `pages.dev` comme URL principale.

La création publique d’une entreprise est désormais bloquée en SQL. Les
créations de comptes prévues par une invitation d’équipe ou de portail restent
disponibles, car elles sont déjà contrôlées par un jeton personnel. Ne pas
désactiver globalement les inscriptions Supabase : cela casserait ces
invitations. Un compte créé sans demande acceptée ne peut ouvrir aucun espace.

## 6. SMTP Auth Supabase

Dans `Authentication > SMTP Settings`, activer le SMTP personnalisé Brevo :

```text
Sender name: NCR Suite
Sender email: contact@ncr-suite.fr
Host, port, username, password: valeurs affichées dans votre compte Brevo
```

Dans `Authentication > Email Templates`, remplacer le logo, les titres et les
textes avec les fichiers prêts à l’emploi indiqués dans
`docs/SUPABASE_AUTH_EMAILS_V2.22.0.md`. Conserver les variables Supabase des
liens. Utiliser `contact@ncr-suite.fr` comme adresse de réponse. Ainsi, même les
e-mails de confirmation des invitations externes ne sont plus envoyés par
l’expéditeur Supabase par défaut.

## 7. GitHub

Décompresser le ZIP du patch à la racine du dépôt GitHub. Conserver exactement
les dossiers `src`, `public`, `functions`, `supabase`, `scripts` et `docs`.
Remplacer les fichiers portant le même nom, puis valider le commit.

Ne pas envoyer `node_modules` ni `dist`.

## 8. Variables Cloudflare Pages

Dans `Workers & Pages > NCR Suite > Settings > Variables and Secrets`, conserver
les variables Supabase existantes et ajouter :

```text
VITE_TURNSTILE_SITE_KEY=VOTRE_CLE_SITE_TURNSTILE
VITE_LEGAL_COMPANY_NAME=VOTRE_RAISON_SOCIALE
VITE_LEGAL_COMPANY_ADDRESS=VOTRE_ADRESSE_COMPLETE
VITE_LEGAL_COMPANY_SIRET=VOTRE_SIRET
VITE_LEGAL_PUBLICATION_DIRECTOR=NOM_DU_DIRECTEUR_DE_PUBLICATION
NCR_CANONICAL_REDIRECT_ENABLED=false
```

Les quatre variables légales sont obligatoires avant l’ouverture publique.
Relancer un déploiement après chaque modification d’une variable `VITE_`.

## 9. Domaine, DNS et e-mails

Suivre `docs/DOMAINE_EMAILS_V2.22.0.md`. Quand `https://ncr-suite.fr` fonctionne
avec un certificat valide, passer :

```text
NCR_CANONICAL_REDIRECT_ENABLED=true
```

Puis relancer un dernier déploiement. `ncrsuite.pages.dev` et
`www.ncr-suite.fr` redirigeront alors vers `https://ncr-suite.fr` en conservant
le chemin.

## 10. Cache PWA

Après le déploiement :

1. fermer tous les onglets NCR Suite ;
2. rouvrir `https://ncr-suite.fr` ;
3. actualiser une fois ;
4. fermer et rouvrir la PWA installée sur ordinateur ;
5. refaire le contrôle sur mobile.

Le cache attendu est :

```text
ncr-suite-shell-v2.22.0-commercial-launch
```

## 11. Test complet

1. Envoyer une demande depuis `/demande-acces`.
2. Ouvrir `Administration NCR > Demandes d’accès`.
3. Accepter la demande.
4. Vérifier la réception depuis `contact@ncr-suite.fr`.
5. Ouvrir le lien, choisir le mot de passe et terminer la configuration.
6. Se déconnecter puis se reconnecter.
7. Tester `Mot de passe oublié`.
8. Contrôler SPF, DKIM et DMARC dans les en-têtes reçus.
9. Ouvrir `Administration NCR > Surveillance`.
10. Cocher les neuf validations uniquement après leur test réel, puis
    enregistrer le contrôle.

## Retour arrière

En cas de problème avant l’ouverture, remettre temporairement
`NCR_CANONICAL_REDIRECT_ENABLED=false` et restaurer le déploiement Cloudflare
V2.21.2. Ne pas supprimer manuellement les tables de la migration 088. Utiliser
la sauvegarde Supabase si un retour de base est réellement nécessaire.
