# Correctif de validation NCR Suite V2.21.2

## Objet

Ce correctif traite les deux alertes restantes après le premier contrôle de production :

- le rapport comptait comme anonymes les droits `PUBLIC` hérités par défaut sur les fonctions PostgreSQL ;
- le contrôle des demandes de modules Formation reprenait à tort le verdict global de l’ancien rapport V2.20.

## Sécurité des fonctions

La migration 085 mémorise d’abord les permissions effectives de chaque fonction pour les utilisateurs connectés et les traitements de service. Elle retire ensuite l’exécution héritée par `PUBLIC` et par le rôle anonyme.

Les permissions mémorisées sont restaurées pour :

- les utilisateurs authentifiés ;
- les traitements utilisant le rôle de service.

Cette méthode évite d’ouvrir une fonction qui était auparavant réservée à un traitement interne.

Seules 22 fonctions nécessaires aux réservations publiques, questionnaires Formation et pages d’invitation reçoivent ensuite un droit anonyme explicite.

Les permissions par défaut sont également corrigées pour les prochaines migrations : les futures fonctions ne seront plus anonymes par héritage.

## Modules Formation

Le contrôle **Demandes de modules Formation** dépend désormais uniquement du nombre réel de demandes âgées de plus de sept jours :

- zéro demande donne le statut **Validé** ;
- une ou plusieurs demandes donnent un avertissement à traiter dans **Abonnements** ;
- une autre anomalie provenant de l’ancien rapport V2.20 n’est plus affichée sous ce mauvais intitulé.

## Application

### 1. Supabase

Exécuter intégralement :

`supabase/migrations/085_production_validation_security_correction.sql`

La migration est idempotente et conserve la version active `2.21.2`.

### 2. GitHub

Envoyer tous les fichiers du correctif en conservant leur arborescence. La version de `package.json` et le cache PWA restent inchangés.

### 3. Cloudflare

Le dépôt peut déclencher un nouveau build, qui doit continuer d’afficher :

```text
ncr-suite@2.21.2
```

Les trois contrôles automatiques doivent réussir.

### 4. Vérification

1. Ouvrir **Administration NCR > Surveillance**.
2. Cliquer sur **Relancer** dans la validation production finale.
3. Vérifier que **Erreurs des navigateurs** reste validé.
4. Vérifier que **Demandes de modules Formation** affiche `0 demande` et **Validé**.
5. Vérifier le résultat de **RLS et fonctions publiques**.
6. Effectuer les sept contrôles manuels avant d’enregistrer le verdict.

Si la ligne RLS indique encore une anomalie après la migration, le rapport **Diagnostic > Sécurité des accès** donnera alors un nombre réduit correspondant à une vraie table ou fonction à examiner, et non aux permissions anonymes héritées.
