# Correctif final de sécurité NCR Suite V2.21.2

## Pourquoi 222 anomalies restaient affichées

La migration 085 a correctement supprimé les droits anonymes hérités. Le
contrôle est ainsi passé de 658 à 222 anomalies et le faux blocage des modules
Formation a disparu.

Les définitions actuelles du dépôt possèdent déjà un `search_path` explicite.
En revanche, les anciennes fonctions déjà créées dans Supabase conservent leur
configuration d'origine tant que leur migration historique n'est pas rejouée.
Le rapport de production détecte précisément ces fonctions historiques.

Il ne faut pas rejouer les anciennes migrations. La migration 086 corrige
directement leur configuration sans remplacer leur code, leurs paramètres ou
leurs permissions.

## Ce que corrige la migration 086

- elle interdit aux rôles applicatifs de créer des objets dans le schéma
  `public` ;
- elle conserve leur droit normal d'utiliser ce schéma ;
- elle ajoute un chemin de recherche sûr à chaque ancienne fonction
  `SECURITY DEFINER` qui n'en possède pas ;
- elle conserve le code et les droits installés par la migration 085 ;
- elle annule toute l'opération si une fonction concernée reste non sécurisée ;
- elle inscrit le nombre de fonctions corrigées dans le journal d'audit.

La migration est idempotente et ne modifie aucune donnée métier.

## Ordre d'application

### 1. Supabase

Exécuter uniquement :

`supabase/migrations/086_security_definer_search_path_hardening.sql`

Attendre le message `Success`. Ne pas rejouer les migrations 084 ou 085.

### 2. GitHub

Envoyer tous les fichiers de ce correctif en conservant leur arborescence.
La version reste `2.21.2` et le cache PWA reste
`ncr-suite-shell-v2.21.2-final-production-validation`.

### 3. Cloudflare

Attendre la fin du build automatique. Il doit afficher
`ncr-suite@2.21.2` et valider les trois contrôles du dépôt.

### 4. Cache PWA

Aucun nouveau cache n'est créé, car l'interface n'est pas modifiée. Fermer puis
rouvrir l'application suffit avant le contrôle final.

### 5. Tests

1. Ouvrir **Administration NCR > Surveillance**.
2. Cliquer sur **Relancer**.
3. Vérifier que **RLS et fonctions publiques** est validé.
4. Vérifier que **Erreurs des navigateurs** reste à zéro.
5. Vérifier que **Demandes de modules Formation** reste validé.
6. Tester une réservation publique, un questionnaire Formation et une page
   d'invitation.
7. Cocher uniquement les sept confirmations réellement testées.
8. Enregistrer le contrôle final.

Si la ligne de sécurité n'est pas validée après la migration 086, le nombre
restant correspond alors à une table RLS réellement à examiner. Il ne faut pas
cocher la validation finale avant son analyse.
