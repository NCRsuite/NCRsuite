# Correctif final des accès NCR Suite V2.21.2

## Diagnostic confirmé

Le contrôle Supabase a confirmé la répartition exacte :

- 0 table sans RLS ;
- 34 tables avec RLS et sans politique ;
- 0 fonction `SECURITY DEFINER` sans chemin sécurisé ;
- 188 fonctions appartenant à des extensions PostgreSQL encore autorisées pour
  `PUBLIC` et `anon`.

Le diagnostic ACL confirme également que le propriétaire et l'accordeur de ces
188 droits sont tous les deux `supabase_admin`, tandis que le SQL Editor lance
la requête sous `postgres`. Le test de propriété a identifié
`cash_dist(money,money)`, une fonction de l'extension `btree_gist`.

Ces fonctions ne sont pas des RPC NCR Suite. Elles sont installées, possédées
et mises à jour avec leurs extensions. Elles ne doivent donc pas être
réattribuées ou modifiées par une migration applicative.

## Classification des fonctions

La migration 087 utilise `pg_depend` et `pg_extension`, les catalogues officiels
de PostgreSQL, pour distinguer :

- les fonctions appartenant à une extension, inventoriées sous
  `extension_public_functions` ;
- les 22 véritables parcours publics NCR Suite ;
- toute autre fonction applicative accessible anonymement, qui reste une
  anomalie bloquante.

Aucun propriétaire, rôle, droit d'extension ou code de fonction n'est modifié.
La transaction est automatiquement annulée si une véritable fonction
applicative non autorisée reste publique.

## Tables fermées par RLS

Une table avec RLS activé et sans politique applique un refus total. Les 34
tables concernées restent inventoriées dans le rapport sous
`sealed_by_rls_tables`, mais ne sont plus comptées comme une exposition.

## Application

### 1. Supabase

Exécuter uniquement :

`supabase/migrations/087_final_public_function_acl_cleanup.sql`

Attendre le message `Success`. Ne pas rejouer les migrations précédentes.

### 2. GitHub

Décompresser le patch et envoyer les fichiers en conservant leur arborescence.
La version reste `2.21.2`.

### 3. Cloudflare

Attendre le build `ncr-suite@2.21.2`. Les trois contrôles doivent réussir.

### 4. Cache PWA

Le cache ne change pas. Fermer puis rouvrir l'application suffit.

### 5. Validation

1. Ouvrir **Administration NCR > Surveillance**.
2. Cliquer sur **Relancer**.
3. Vérifier que **RLS et fonctions publiques** est validé.
4. Vérifier que les erreurs navigateur et les demandes Formation restent
   validées.
5. Tester les trois parcours publics : réservation, questionnaire et
   invitation.
6. Terminer les sept confirmations manuelles et enregistrer le verdict.
